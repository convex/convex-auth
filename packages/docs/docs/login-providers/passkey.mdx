The passkey component lets you implement passkey-based login.

A passkey replaces the password with a key pair that stays on the user's device:
users can store the passkey on their device (protected by a fingerprint,
a face scan, or PIN), or use an external hardware security key.
Your app never handles a secret that can be phished or reused.

The `setupUsernamePasskey` provider implements an _identifier-first_ flow:
your login page has a single username field. A free username creates a new
account with a new passkey; an existing username asks for a passkey of that
account.

### Set up user creation

each time someone signs in belongs there, so `createUser` only has to handle
what is true at creation time. Leave it out if there is nothing to do.

```

`rpId` and `origin` bind the passkeys to your app:

- `rpId` is the _relying party ID_: the domain the passkeys belong to, without
  a scheme or a port (`localhost` in development, `example.com` in
  production). Browsers only offer a passkey to a page whose domain is the
  `rpId` or a subdomain of it.
- `origin` is the full origin the login page is served from, including the
  scheme and the port (`http://localhost:5173` for the Vite dev server). The
  component rejects a passkey sign-in that comes from any other origin.

:::warning

Passkeys are permanently bound to their `rpId`: a passkey created with `rpId:
"localhost"` can never be used on your production domain. Set both values to
the production domain before you deploy.

:::

</Step>

### Set up the authentication UI

In your front-end, set up a route for logging in. Because the flow is
identifier-first, the same page and the same field serve account creation and
login.

While the hook is mounted, it also lets the browser offer the passkeys it has
stored in the autocompletion list of the username field. The field must carry
`autoComplete="username webauthn"` for the browser to do that.

:::warning

The browser allows only one of these autofill requests at a time, so you
should not mount the `useSignInWithUsernamePasskey` hook multiple times
simultaneously.

## Going further

### Allowing users to manage their passkeys

When your app supports passkeys, it is highly recommended to allow users to add multiple passkeys. This is especially useful for users who use multiple devices, or hardware authenticators.

<Steps>

<Step>

#### Make sure the Convex functions for passkey managements are exposed

In `convex/auth.ts`, make sure the following functions are exported:
`listPasskeys`, `renamePasskey`, `startAddPasskey`, `verifyAddPasskey`,
`finishAddPasskey`, `startRemovePasskey`, and `finishRemovePasskey`.

```ts file="examples/react-passkey/convex/auth.ts" title="convex/auth.ts" highlight="  listPasskeys,...  finishRemovePasskey,"

```

</Step>

<Step>

#### Build the passkey management page

In your app’s settings page, add the UI code for adding, renaming, and removing passkeys. This code uses the `useAddPasskey` and `useRemovePasskey` hooks provided by Convex Auth, and the `renamePasskey` mutation.

We recommend copying the following component into your app, adapting it to your app’s design system, and rendering it on your settings page:

```tsx file="examples/react-passkey/src/PasskeySettings.tsx" title="src/PasskeySettings.tsx"

```

</Step>

</Steps>
