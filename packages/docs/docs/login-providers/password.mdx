The password component lets you implement password-based login. It automatically handles subtle security details of password handling, including hashing (with Argon2id), rate limiting, and validation.

## Setting up username + password login in your app

<Step>

<Step>

### Install the components

Register the password component and the username component alongside the core
in `convex/convex.config.ts`. The username component stores which user each
username identifies:

```ts file="examples/react-password/convex/convex.config.ts" title="convex/convex.config.ts" highlight="import passwordProvider from" highlight="import username from" highlight="app.use(passwordProvider)" highlight="app.use(username)"

```

</Step>

<Step>

### Add a `users` table to the schema

Add an empty `users` table to your schema in `convex/schema.ts`. The username
component keeps the username, so the table does not need a field for it.

Convex Auth will create a row for each account. You can also add application-specific fields to this table if necessary.

```ts file="examples/react-password/convex/schema.ts" title="convex/schema.ts" highlight="users: defineTable({}),"

```

</Step>

<Step>

### Set up user creation

Write a `createUser` mutation that creates a row in your `users` table and
returns its id. The provider calls it the first time it sees an account.

You can also attach an optional `onSignIn` mutation, called with the resolved
`userId` on every sign-in, the first one included. Anything you want to happen
each time someone signs in belongs there, so `createUser` only has to handle
what is true at creation time. Leave it out if there is nothing to do.

```ts file="examples/react-password/convex/users.ts" title="convex/users.ts"

```

</Step>

<Step>

### Set up the public backend functions

Set up the password provider with `setupUsernamePassword` and export the
sign-up and sign-in mutations it hands back once you attach the callback that
creates your user rows, in `convex/auth.ts`:

```ts file="examples/react-password/convex/auth.ts" title="convex/auth.ts" highlight="import { setupUsernamePassword }" highlight="  signUpWithUsernamePassword,...}).attachUserCallbacks({ createUser: internal.users.createUser });"

```

</Step>

<Step>

### Set up the provider on the client

Wrap your app in `ConvexAuthProvider`, passing it the `refreshSession` and
`signOut` mutations in `src/main.tsx`:

```tsx file="examples/react-password/src/main.tsx" title="src/main.tsx" highlight="import { ConvexAuthProvider }" highlight="<ConvexAuthProvider...>" highlight="</ConvexAuthProvider>"

## Going further

### Allowing users to change their password

It is highly recommended that you implement a feature allowing users in your app to change their password, because a user might need it if they accidentally leak their password.

<Steps>

<Step>

#### Export the `changePassword` function

In `convex/auth.ts`, export the `changePassword` mutation next to `signUpWithUsernamePassword` and `signInWithUsernamePassword`:

```ts file="examples/react-password/convex/auth.ts" title="convex/auth.ts" highlight="changePassword"

```

</Step>

<Step>

#### Expose the username of the signed-in user

The change-password form includes a hidden username field, so that password managers know which login to update. Write a query that returns the username of the signed-in user:

```ts file="examples/react-password/convex/currentUser.ts" title="convex/currentUser.ts"

```

</Step>

<Step>

#### Build the change-password form

Copy the following component into your app, adapt it to your design system, and render it on your settings page.

The form asks users to re-authenticate by entering their current password for security reasons.

```tsx file="examples/react-password/src/PasswordSettings.tsx" title="src/PasswordSettings.tsx"

```

</Step>

</Steps>

:::info[Recommendation: implement the well-known change-password URL]

Password managers open
[`/.well-known/change-password`](https://w3c.github.io/webappsec-change-password-url/)
on your website when a user wants to change their password. To provide a good
user experience, we recommend redirecting that path to your settings page.

:::
