The email short code sign-in method lets users sign in with an 8-digit code
that they receive by email and type in your app. There is no password, and
one form serves both sign-in and sign-up:

- A user who has an account enters the code and is signed in.
- A user who has no account enters the code, and the account is created at
  that moment. No account exists for an address until its owner enters a
  code.

The form gives the same result whether or not the address has an account.

A code works once, for 10 minutes, and only in the browser (or app) that
asked for it: the client keeps a secret in its storage, and the sign-in
requires both that secret and the code. Thus a code that another person
reads, for example in a notification on a lock screen, is not sufficient to
sign in.

Compared to a [magic link](./magic-link.mdx), the user stays on the page of
your app: they read the code on any device, and type it where they started.
An 8-digit code is easier to guess than a link, thus the method limits the
incorrect codes (see [Rate limits](#rate-limits)).

Emails are sent through the
[`@convex-dev/resend`](https://www.convex.dev/components/resend) component.

## Setting up email short code login in your app

<StepByStep>

<Step title="Follow the “Getting started” guide">

<Step title="Set up Resend">

This method uses [Resend](https://resend.com) to send the sign-in emails.

You will need a domain to send these emails from.

Before going further:

1. [Create a Resend account](https://resend.com/signup)
2. [Set up your domain in Resend](https://resend.com/docs/add-a-domain)
3. [Create a Resend API key](https://resend.com/docs/create-an-api-key)

Then connect Resend to your Convex deployment:

```bash
npm install @convex-dev/resend
npx convex env set RESEND_API_KEY # Press Enter then enter your Resend API key
npx convex env set SENDER_EMAIL no-reply@my-domain.example # Replace this with an email address in your verified domain
npx convex env set SENDER_NAME "My App" # Optional: replace this with the sender name of your emails
npx convex env set SITE_URL https://my-app.example # Replace this with the origin of your frontend, where users type the code. Without it, the origin is http://localhost:5173
```

</Step>

## Limitations

- **Users can't change their email address yet.** The change-email flow of
  the [email + password](./email-password.mdx) method requires the current
  password, and an account created with a code has none.
- **The text of the email can't be customized yet.**
- **The code length is fixed** at 8 digits.

## Rate limits

This method rate-limits the emails that it sends and the incorrect codes
that it accepts. When a limit is reached, the call returns a `RATE_LIMITED`
error with `retryAfterMs`, the number of milliseconds until the next attempt
can succeed. Show it to the user, as `signIn.tsx` does above.

Each limit is a token bucket: the user can make as many attempts as the
capacity at once, then the bucket refills at a steady rate.

| Limit                                   | Applies to                                                       | Capacity | Refill         |
| --------------------------------------- | ---------------------------------------------------------------- | -------- | -------------- |
| Emails per destination address          | Sign-in codes sent to one address                                | 5        | 1 every 12 min |
| Emails per client IP                    | The same emails, sent from one client IP to any address          | 20       | 1 every 3 min  |
| Incorrect codes per destination address | Incorrect codes entered for one address, for all of its sign-ins | 10       | 1 every 6 min  |

In addition, each sign-in accepts 5 incorrect codes. The fifth incorrect code
returns `INCORRECT_CODE` with `attemptsLeft: 0` and ends the sign-in: the
user must ask for a new code. A correct code never uses a token.

Anyone can ask for codes for an address and enter incorrect ones, so a person
who knows the address of a user can use up the limits of that address and
keep the user from signing in for a while. If this is a concern for your app,
offer a second sign-in method, such as [passkeys](./username-passkey.mdx).

The limit of emails per destination address is shared with the other emails
of the email component, such as the password reset links of the email +
password method.

These values aren't configurable yet.
