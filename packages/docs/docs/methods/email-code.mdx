The email code sign-in method signs users in with a short code sent to their
email address. There is no password. The same two steps sign up a new user and
sign in an existing one:

1. The user enters their email address, and the app sends a code to it.
2. The user types the code in the app, and the app signs them in.

When a user has already verified the address, they sign in to their account,
whichever method they signed up with. Otherwise, the method creates a user
with your `createUser` mutation, and the address becomes its primary email
address.

The user types the code where they started, so the flow works where a link
does not: in an installed web app, when the mail app opens links in its own
browser, on another device, or in a native app.

Emails are sent through the
[`@convex-dev/resend`](https://www.convex.dev/components/resend) component.

## Options

`setupEmailCode` takes these options besides `component` and `emailSender`:

| Option          | Default                         | Bounds          |
| --------------- | ------------------------------- | --------------- |
| `codeLength`    | 8 digits                        | 6 to 10 digits  |
| `ttlMs`         | 10 minutes                      | 1 to 30 minutes |
| `email.subject` | `"{code} is your sign-in code"` |                 |
| `email.intro`   | `"Enter this code to sign in:"` |                 |

`{code}` in the subject is replaced by the code. A code in the subject shows
in the notification of the email, and some phones offer to fill it in. Remove
`{code}` from the subject if you don't want the code to show on a locked
screen.

The email has the intro, the code on its own line, how long the code works,
and a line that tells the user not to share the code.

## How a code is protected

- A code works only in the browser or app that asked for it. When it asks,
  the client gets a secret and keeps it in its storage. The code works only
  with that secret, thus a code read from the email alone cannot sign anyone
  in.
- A code works once, and only until it expires.
- After 5 wrong codes, the code stops working, and the user must ask for a new
  one.
- The code is drawn uniformly at random. The component stores only hashes of
  the code and of the secret.
- When the user asks for a new code, the client keeps only the newest secret.
  Tell the user to use the newest email.

With 8 digits, 5 attempts per code, and the limit of 5 codes per address per
hour, an attacker who knows the address has about 1 chance in 4 million per
hour to guess a code, and each try sends an email to the owner of the address.
With 6 digits, the chance is about 1 in 40,000 per hour.

A code does not protect against a user who reads it out to someone else, for
example to a caller who pretends to be support. That person asked for the code
in their own browser, thus the code signs them in. A phishing site that relays
the code to your app in real time also works. If this matters for your app,
offer [passkeys](./username-passkey.mdx) too.

## What the response hides

Starting a sign-in returns the same response whether or not a user has
verified the address. It fails only for a malformed address or when a rate
limit is reached, and these limits count every address the same.

Other parts of your app can still tell whether an address has an account. For
example, the sign-up of the [email + password](./email-password.mdx) method
returns `EMAIL_TAKEN`. And once the user types the code, your app knows
whether they signed in to an existing account or a new one.

## Which account a code signs in to

The method looks the address up in the verified addresses of the email
component. An address that a user verified with the email + password method,
or that your app added to their account, signs in to that user.

An address that only an OAuth provider gave you, for example in the Google
profile, is not a verified address of the email component. A code sent to it
creates a new user, unless your app adds the address to the existing one.

## Rate limits

When a limit is reached, the start returns a `RATE_LIMITED` error with
`retryAfterMs`, the number of milliseconds until the next attempt can succeed.

| Limit                          | Applies to                          | Capacity | Refill         |
| ------------------------------ | ----------------------------------- | -------- | -------------- |
| Emails per destination address | Codes and links sent to one address | 5        | 1 every 12 min |
| Emails per client IP           | Codes and links sent from one IP    | 20       | 1 every 3 min  |
| Attempts per code              | Wrong codes typed for one code      | 5        | None           |

The limits per address and per IP are shared with the links that the email
component sends for other methods.
