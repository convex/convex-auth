The OAuth components and their sign-in methods (set up with `setupApple`,
`setupGoogle`, `setupGithub`, and `setupDiscord`) allow your users to log in via
their existing Apple, Google, GitHub, or Discord accounts.

The steps below will guide you through configuring Apple, Google, GitHub,
and/or Discord login. In the end, your Convex deployment will host HTTP routes for
handling the OAuth callbacks and redirect back to your application for handling
the result.

:::info

Support for using other OAuth identity providers is coming soon.

:::

## Common setup

These steps are the same whichever provider you use. Each identity provider
gets its own component, so an app offering both Google and GitHub login
repeats the provider-specific steps below for each of them.

<StepByStep>

<Step title="Follow the “Getting started” guide">

First, install Convex Auth and set up the core as described in the
[Getting started](../getting-started.mdx) guide.

</Step>

Convex Auth will create a row for each account. You can also add application-specific fields to this table if necessary.

<TabItem value="Apple" label="Apple">

<StepByStep>

<Step title="Register the Services ID and the key">

Sign in with Apple is set up in [Certificates, Identifiers &
Profiles](https://developer.apple.com/account/resources/), and needs a paid
Apple Developer Program membership.

:::info

The callback lives on your deployment's `convex.site` host rather than on your
app frontend, so a cloud deployment works as it is and your app frontend can
stay on `localhost`. Apple never sees where the flow returns to.

Apple does reject `localhost` and IP addresses as return URLs, so a deployment
that is not publicly reachable, meaning a local backend or self-hosting on
localhost, needs a public HTTPS hostname before Apple will accept its callback.

:::

1. **Register an App ID with Sign in with Apple enabled**, as a primary App
   ID. Websites attach to an App ID, so you need one even with no native app.
2. **Register a Services ID.** Its identifier (something like
   `com.example.app.web`) is your client ID. Select Sign in with Apple, click
   Configure, choose the App ID from step 1, and under Website URLs enter your
   deployment's site host (`happy-animal-123.convex.site`) as the domain and
   `https://happy-animal-123.convex.site/oauth/apple/callback` as the return
   URL. Nothing has to be uploaded to your server. Individual accounts can
   register 10 website URLs, organizations 100.
3. **Create a key** with Sign in with Apple enabled, choosing the App ID from
   step 1 as its primary App ID, and download its `AuthKey_XXXXXXXXXX.p8`
   file. Apple only lets you download it once. The 10-character `XXXXXXXXXX`
   is your key ID.
4. **Note your team id**, the 10-character value in the top right of the
   developer account page.

Print your `CONVEX_SITE_URL`, which holds that site host, with the Convex CLI.

```sh
npx convex env get CONVEX_SITE_URL
```

</Step>

<Step title="Set the environment variables">

Store all four values as [environment
variables](https://docs.convex.dev/production/environment-variables#declaring)
on your Convex deployment. The private key is multi-line, so read it from the
file rather than passing it as an argument.

Apple issues no static client secret. The component signs a short-lived one
for each token exchange out of the team id, key id, and private key, which is
why it takes four values where the other providers take two.

```sh
npx convex env set AUTH_APPLE_CLIENT_ID YOUR_SERVICES_ID
npx convex env set AUTH_APPLE_TEAM_ID YOUR_TEAM_ID
npx convex env set AUTH_APPLE_KEY_ID YOUR_KEY_ID
npx convex env set AUTH_APPLE_PRIVATE_KEY < AuthKey_XXXXXXXXXX.p8
```

</Step>

<Step title="Install the component">

Register the Apple OAuth component alongside the core in
`convex/convex.config.ts`. Declare the environment variables from the previous
step in your application's `env`, then pass their values to the component.

```ts file="examples/react-apple/convex/convex.config.ts" title="convex/convex.config.ts" highlight="import authApple from" highlight="app.use(authApple, {...});" highlight="AUTH_APPLE_CLIENT_ID:...AUTH_APPLE_PRIVATE_KEY: v.string(),"
```

</Step>

<Step title="Set up user creation">

Write a `createUser` mutation that creates a row in your `users` table and
returns its id. The method calls it the first time it sees an account.

Apple is different from the other providers here. It sends the user's name
only on the very first authorization and never again, so store it when it
arrives and leave the stored one alone on later sign-ins. The `onSignIn`
mutation in this example does exactly that. The name is also the one part of the profile
that reaches you through the browser rather than from Apple directly, so treat
it as untrusted text entered by a user.

```ts file="examples/react-apple/convex/users.ts" title="convex/users.ts"
```

</Step>

<Step title="Set up the public backend functions">

Set up the `apple` method with `setupApple` and export the mutations for
starting and completing OAuth login that it hands back once you attach the
callbacks, in `convex/auth.ts`:

```ts file="examples/react-apple/convex/auth.ts" title="convex/auth.ts" highlight="import { setupApple }" highlight="export const { startSignInWithApple...});"
```

</Step>

<TabItem value="Google" label="Google">

<StepByStep>

<Step title="Register the OAuth app">

To allow users to log in to your app via Google, register an OAuth application
with Google by following the [Google OIDC
instructions](https://developers.google.com/identity/openid-connect/openid-connect#appsetup).

Google asks for a redirect URI when you register the application. Use your
`CONVEX_SITE_URL` followed by `/oauth/google/callback`, for example
`https://happy-animal-123.convex.site/oauth/google/callback`. Print your
`CONVEX_SITE_URL` with the Convex CLI.

```sh
npx convex env get CONVEX_SITE_URL
```

</Step>

<Step title="Set the environment variables">

Google will assign a unique client ID and client secret to your application.
You will store those values as [environment
variables](https://docs.convex.dev/production/environment-variables#declaring)
on your Convex deployment.

```sh
npx convex env set AUTH_GOOGLE_CLIENT_ID YOUR_GOOGLE_OAUTH_CLIENT_ID
npx convex env set AUTH_GOOGLE_CLIENT_SECRET # Press Enter then enter your Google client secret
```

</Step>

<Step title="Install the component">

Register the Google OAuth component alongside the core in
`convex/convex.config.ts`. Declare the environment variables from the previous
step in your application's `env`, then pass their values to the component.

```ts file="examples/react-google/convex/convex.config.ts" title="convex/convex.config.ts" highlight="import authGoogle from" highlight="app.use(authGoogle, {...});" highlight="AUTH_GOOGLE_CLIENT_ID:" highlight="AUTH_GOOGLE_CLIENT_SECRET:"
```

</Step>

<Step title="Set up user creation">

Write a `createUser` mutation that creates a row in your `users` table and
returns its id. The method calls it the first time it sees an account.

```ts file="examples/react-google/convex/users.ts" title="convex/users.ts"
```

</Step>

<Step title="Set up the public backend functions">

Set up the `google` method with `setupGoogle` and export the mutations for
starting and completing OAuth login that it hands back once you attach the
callback that creates your user rows, in `convex/auth.ts`.

Next to `createUser`, you can also attach an optional `onSignIn` mutation,
called with the resolved `userId` on every sign-in, the first one included.
Anything you want to happen each time someone signs in belongs there, so
`createUser` only has to handle what is true at creation time.

```ts file="examples/react-google/convex/auth.ts" title="convex/auth.ts" highlight="import { setupGoogle }" highlight="export const { startSignInWithGoogle...).attachUserCallbacks({ createUser: internal.users.createUser });"

</Step>

<TabItem value="Discord" label="Discord">

<StepByStep>

<Step title="Register the OAuth app">

To allow users to log in to your app via Discord, create an application in
the [Discord Developer Portal](https://discord.com/developers/applications).

On the application's OAuth2 page, add a redirect URI under Redirects. Use your
`CONVEX_SITE_URL` followed by `/oauth/discord/callback`, for example
`https://happy-animal-123.convex.site/oauth/discord/callback`. Print your
`CONVEX_SITE_URL` with the Convex CLI.

```sh
npx convex env get CONVEX_SITE_URL
```

</Step>

<Step title="Set the environment variables">

The same OAuth2 page shows your application's client ID. Discord does not
show an existing client secret: click "Reset Secret" to generate one, and copy
it then. You will store those values as [environment
variables](https://docs.convex.dev/production/environment-variables#declaring)
on your Convex deployment.

```sh
npx convex env set AUTH_DISCORD_CLIENT_ID YOUR_DISCORD_OAUTH_CLIENT_ID
