Convex Auth supports server-side rendering (SSR) with the Next.js App Router.
In an SSR app, sign-in, refresh, and sign-out run on your Next.js server rather
than in the browser:

- The **refresh token** is stored in an `httpOnly` cookie, so it never reaches
  client JavaScript.
- The **access token** is available to both sides: Server Components use it to
  run authenticated Convex queries during rendering, and the browser uses it to
  authenticate the Convex client.

The sign-in method guides still apply. Your Convex backend and the method
hooks you call from your UI are the same as in a single-page app. What changes
is how the frontend connects to Convex Auth. This guide covers that wiring.
[Sign-in methods with Next.js](/ssr-nextjs/login-providers) covers the
method-specific differences.

The code below comes from the
[Next.js example](https://github.com/convex/convex-auth/tree/reboot/examples/nextjs),
which supports username + password, anonymous, and GitHub sign-in.

### Set up the backend for your sign-in methods

Follow the backend steps of the guide for each sign-in method you want to use:
install the components, add the `users` table, set up user creation, and export
the public functions from `convex/auth.ts`.

<Callout type="info">
  Don't follow the frontend steps (“Set up the provider on the client” and “Set
  up the authentication UI”). The rest of this guide replaces them.
</Callout>

The SSR helpers need one more function from the core than a single-page app
does. Export `isAuthenticated` next to `signOut` and `refreshSession`. The
server uses it to check access tokens with your deployment, so it doesn't trust
a cookie only because it can decode it.

function in your app that creates a session, like signing up or signing in. See

each method needs.

<Step>

### Set up the Next.js helpers

Create `src/lib/convexAuth.tsx` and call `setupConvexAuthNextjs`. It returns
the parts of the integration that are specific to Next.js:

- `convexAuthNextjsProxy` builds the Next.js proxy (`proxy.ts`).
- `nextjsProxyRedirect` redirects a request from inside the proxy.
- `convexAuthNextjsAccessToken` reads the access token in a Server Component.
- `isAuthenticatedNextjs` checks whether the current request is signed in.
- `ConvexAuthNextjsServerProvider` replaces `ConvexAuthProvider`.

<Step>

### Set up the proxy

Create `proxy.ts` at the root of your app. The proxy runs before each page
request. It refreshes the session if the access token is about to expire, so
Server Components always see a current token. It also lets you redirect
requests based on whether the user is signed in.

  ../../../../../examples/nextjs/proxy.ts
</include>

<Callout type="warn">
  Keep the `/auth` routes out of the `matcher`. Those routes set their own
  cookies.
</Callout>

</Step>

<Step>

### Set up the provider

Wrap your app in `ConvexAuthNextjsServerProvider` in the root layout. It is a
Server Component that reads the access token from the cookie and renders the
client-side `ConvexAuthNextjsProvider`, so the Convex client is ready to
authenticate when the page loads. Use it in place of `ConvexAuthProvider` and
`ConvexProvider`.

<Step>

### Render authenticated data on the server

In a Server Component, get the access token with `convexAuthNextjsAccessToken`
and pass it to `preloadQuery` from `convex/nextjs`. The page renders with the
signed-in user's data, and the client continues the query live with
`usePreloadedQuery`:

<include
  lang="tsx"
  meta='title="app/page.tsx" highlight="const token = await convexAuthNextjsAccessToken();" highlight="{ token: token ?? undefined },"'
>
  ../../../../../examples/nextjs/app/page.tsx
</include>

To decide on the server whether the user is signed in, use
`isAuthenticatedNextjs()` and not the presence of a token.
`convexAuthNextjsAccessToken` only checks that the token hasn't expired.
`isAuthenticatedNextjs` checks the token's signature with your deployment.

</Step>

<Step>

### Use Convex Auth in Client Components

Import `useAuthActions` and `useAuthToken` from `@convex-dev/auth/react`, the
same as in a single-page app. Import `useConvexAuth` and the `Authenticated`,
`Unauthenticated`, and `AuthLoading` components from `convex/react`. After you call `signOut`, navigate away from the page so the
proxy can apply your redirects:

<include
  lang="tsx"
  meta='title="app/Dashboard.tsx" highlight="import { useAuthActions, useAuthToken }" highlight="await signOut();"'
>
  ../../../../../examples/nextjs/app/Dashboard.tsx
</include>

For your sign-in and sign-up pages, use the hooks of each sign-in method. See
[Sign-in methods with Next.js](/ssr-nextjs/login-providers).

</Step>

## Deploying

The auth cookies are marked `Secure` (sent only over HTTPS) when `NODE_ENV` is
`production`. That is the case for `next build` and `next start`, but not for
`next dev`, so the cookies also work on `http://localhost`.

The auth routes reject cross-site requests by comparing the request's `Origin`
with its `Host`. If your app runs behind a proxy that rewrites `Host`, add your
public origin to `allowedOrigins` in `setupConvexAuthServer`.
