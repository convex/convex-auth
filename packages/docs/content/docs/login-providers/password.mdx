The password component lets you implement password-based login. It automatically handles subtle security details of password handling, including hashing (with Argon2id), rate limiting, and validation.

### Add a `users` table to the schema

Add an empty `users` table to your schema in `convex/schema.ts`. The username
component keeps the username, so the table does not need a field for it.

Convex Auth will create a row for each account. You can also add application-specific fields to this table if necessary.

<include
  lang="ts"

>
  ../../../../../examples/react-password/convex/schema.ts
</include>

</Step>

<Step>

### Set up user creation

Write a `createUser` mutation that creates a row in your `users` table and
returns its id. The method calls it the first time it sees an account.

You can also attach an optional `onSignIn` mutation, called with the resolved
`userId` on every sign-in, the first one included. Anything you want to happen
each time someone signs in belongs there, so `createUser` only has to handle
what is true at creation time. Leave it out if there is nothing to do.

<include lang="ts" meta='title="convex/users.ts"'>
  ../../../../../examples/react-password/convex/users.ts
</include>

</Step>

<Step>

sign-up and sign-in mutations it hands back once you attach the callback that
creates your user rows, in `convex/auth.ts`:

## Going further

### Allowing users to change their password

It is highly recommended that you implement a feature allowing users in your app to change their password, because a user might need it if they accidentally leak their password.

<Callout
  type="info"
  title="Recommendation: implement the well-known change-password URL"
>
  Password managers open
  [`/.well-known/change-password`](https://w3c.github.io/webappsec-change-password-url/)
  on your website when a user wants to change their password. To provide a good
  user experience, we recommend redirecting that path to your settings page.
</Callout>
