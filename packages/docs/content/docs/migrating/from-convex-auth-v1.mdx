## Schema changes

v2 no longer exports `authTables`. v2 keeps its sessions, accounts, and other
auth data in its own components, and your schema declares only your `users`
table. A v1 `schema.ts` that spreads `...authTables` fails to deploy with:

```
No matching export in "node_modules/@convex-dev/auth/dist/server/index.js" for import "authTables"
```

### Keep the fields of your existing users

The login provider guides add an empty `users` table, but your existing user
documents still have the fields that v1 wrote, so that schema fails
validation, for example with `Object contains extra field isAnonymous that is
not in the validator`. Replace `...authTables` with the `users` table of v1,
which declares the same fields and indexes:

```ts title="convex/schema.ts"
import { defineSchema, defineTable } from "convex/server";
import { v } from "convex/values";

export default defineSchema({
  users: defineTable({
    name: v.optional(v.string()),
    image: v.optional(v.string()),
    email: v.optional(v.string()),
    emailVerificationTime: v.optional(v.number()),
    phone: v.optional(v.string()),
    phoneVerificationTime: v.optional(v.number()),
    isAnonymous: v.optional(v.boolean()),
  })
    .index("email", ["email"])
    .index("phone", ["phone"]),
  // Your other tables…
});
```

If you had already customized the `users` table in v1, keep your version.
v2 doesn't write to these fields: you can remove the ones your app doesn't use
once no document has them.

### The v1 auth tables

v1 also stored its data in the `authSessions`, `authAccounts`,
`authRefreshTokens`, `authVerificationCodes`, `authVerifiers`, and
`authRateLimits` tables of your app. v2 doesn't read or write them. Removing
`...authTables` from your schema doesn't delete them: their documents stay in
your deployment, without a schema. Keep them while you move your users to v2
(for example, the `authAccounts` table links each user to their email address
or OAuth account), then delete them from the dashboard.
